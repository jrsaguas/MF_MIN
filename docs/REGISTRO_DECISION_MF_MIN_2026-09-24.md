# MF_MIN — REGISTRO DE DECISIÓN Y CONTINUIDAD

**Registro:** 2026-09-25 02:22:46 UTC / 2026-09-24 20:22:46 UTC-06:00

## Contexto

La auditoría de V7.1 mostró que el repositorio contiene una base formal sólida alrededor de:

[
langle O,M,A,deltaangle
]

pero también una gran cantidad de capacidades superiores: inferencia, memoria, planificación, aprendizaje, percepción, epistemología, lenguaje, adaptación LLM y simulación.

El problema identificado no fue la existencia de esas capacidades, sino la pérdida de separación conceptual entre:

- qué es fundamental;
- qué es derivado;
- qué es experimental;
- qué es aplicación.

## Decisiones

### D1 — V7.1 queda congelada como baseline

No se modifica destructivamente la versión histórica.

### D2 — El núcleo se fija provisionalmente como

[
MF_{MIN}=langle O,M,A,deltaangle
]

### D3 — La irreducibilidad se cierra operativamente

No se ejecutará otra búsqueda indefinida de componentes eliminables.

### D4 — La siguiente pregunta es constructiva

Se estudiará qué capacidades pueden representarse y construirse usando exclusivamente el núcleo.

### D5 — Las extensiones existentes se conservan

No se eliminarán por el hecho de ser posteriores al núcleo. Se reclasificarán.

### D6 — El proyecto se dividirá en Bloques A–F

A. Especificación formal  
B. Irreducibilidad  
C. Suficiencia constructiva  
D. Reclasificación de V7.1  
E. Experimentos controlados  
F. Gobernanza y evolución

## Razón de la decisión

La finalidad es recuperar la trayectoria original del proyecto sin perder el trabajo de ingeniería acumulado.

El principio rector pasa a ser:

[
	ext{núcleo mínimo}
ightarrow
	ext{expresividad}
ightarrow
	ext{extensiones justificadas}
ightarrow
	ext{capacidades}
]

y no:

[
	ext{funcionalidad}
ightarrow
	ext{más funcionalidad}
ightarrow
	ext{arquitectura cada vez mayor}
]

## Próximo punto de control

El primer entregable de ejecución será la especificación canónica del Bloque A.
